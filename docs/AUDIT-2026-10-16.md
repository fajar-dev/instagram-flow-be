# Audit lanjutan backend dan frontend — 2026-10-16

## Acuan dan cakupan

Audit membandingkan modul fitur dengan contact, user, dan auth: controller tipis, service mengatur use case, repository melalui interface, DI di module, serializer eksplisit, dan service frontend mengembalikan ApiResponse. Pemeriksaan mencakup source aplikasi, import, konfigurasi database/storage, route, test, serta dokumentasi aktif. Tidak ada perubahan migration yang sudah diterapkan atau penghapusan data pengguna.

## Perbaikan

- Penamaan class/type/helper internal `Social*` diganti berdasarkan fitur. Tidak ada lagi repository atau HTTP helper dengan nama modul lama. Entity tetap menunjuk tabel fisik existing secara eksplisit.
- Query browse/overview dipindahkan ke `reporting/repositories/reporting.repository.ts` melalui `IReportingRepository`. Shared `IWorkflowRepository` hanya menangani unit-of-work dan query antrean. Transaksi lintas job/batch/result/revision tetap satu transaksi.
- Controller menggunakan ApiResponse dan serializer milik fitur secara langsung. Helper response generik dihapus. Validasi body hanya di route, kecuali callback n8n yang harus memvalidasi setelah adapter snake_case. Retry job dan akses batch detail melalui service fitur.
- Serializer per entity memakai daftar field eksplisit, seperti contact/user. Penambahan properti entity tidak otomatis mempublikasikannya. JobDetailsSerializer menyusun serializer tiap fitur; ReportingSerializer menambahkan hanya projectName/uploaderName dari join. Settings dan overview sudah berupa DTO eksplisit, bukan entity mentah.
- Dispatcher selalu mengunci batch → job → dispatch. Saat percobaan habis, job dan batch menjadi FAILED dalam transaksi yang sama. Retry mengembalikan batch ke PROCESSING. HTTP webhook tetap di luar transaksi.
- Pagination contact/user/reporting memakai validator bersama: page 1–1.000.000, limit 1–100; input invalid menjadi 422. Default contact/user tetap 10 dan reporting 20.
- Semua service JSON frontend mengembalikan ApiResponse<T>, konsisten dengan contact/user; konsumennya membaca `.data`. Download binary tetap Blob. Header bearer/idempotency dipusatkan, role session memakai UserRole bersama.
- Duplikasi upload avatar pada modal tambah/edit user diganti UserPhotoUpload, memakai useImageUpload existing. Respons upload setelah modal ditutup/preview dihapus diabaikan; object URL dibersihkan. Handler klik global pada modal dihapus agar interaksi form tidak menutup modal.
- Dokumentasi service frontend diperbarui: tidak ada toast, composable Nuxt, navigation, atau catch yang membuang error di service.

## Kompatibilitas yang sengaja dipertahankan

`/api/*`, alias halaman `/social/*`, nama tabel `social_*`, nama migration, konfigurasi `config.social`/env SOCIAL_*, CLI jobs:dispatch/social:admin, serta namespace terjemahan pages.social adalah kontrak existing. Itu bukan implementasi modul kedua. Mengganti semuanya tanpa migrasi konsumen akan merusak data/integrasi/link lama. Folder docs/social menyimpan spesifikasi dan riwayat keputusan, bukan source runtime.

MinIO tetap menggunakan helper storage awal dengan bucket media private terpisah dari avatar. LegacyLocalMediaReader hanya dipakai command import data lama, read-only; tidak dipakai route runtime. Google login, profile, reset password, dan seeder tetap dipertahankan.

## Verifikasi

Regresi mencakup status dispatch terminal dan retry, ACK/claim race, pagination baseline/fitur, kontrak envelope seluruh service JSON, serta pembatasan field serializer. Jalankan backend test/typecheck/build dan frontend test/typecheck/lint/build. Hasil akhir dicatat pada respons audit.

Audit statis dan test bukan jaminan tidak ada bug atau duplikasi semantik sama sekali. Browser UAT tidak diulang setelah penolakan akses origin sebelumnya. n8n/OpenAI/Telegram live tidak dipanggil dalam audit ini; suite memakai adapter eksternal terkontrol.

## Audit lanjutan alur frontend–backend

- Aggregator `src/modules/workflow.module.ts` dihapus. Content, AI Job, Content Review, Integration, dan Reporting mengekspor controller/service langsung. Routes mengimpor modul pemilik. Shared module hanya membangun repository transaksi dan ownership context; tidak mengekspor ulang semua controller. Factory test terisolasi berada di `test/fixtures/workflow.module.ts`, bukan source runtime.
- `config.app.frontendUrl` memakai FRONTEND_URL untuk tautan reset password dan review. APP_URL tetap URL API untuk signed media. Tidak mengubah .env pengguna.
- Batas upload menghitung aset aktif saja. Aset yang diarsipkan tidak menghabiskan kuota.
- Backend menolak retry untuk kegagalan non-retryable; frontend menyembunyikan tombolnya sesuai field yang sama.
- Editor menampilkan loading, mencegah perubahan saat save/reload, dan tidak mengeluarkan toast sukses jika pemuatan ulang revision gagal. Payload requestedOutputs dikunci setelah proses pertama agar retry jaringan menggunakan idempotency key dengan payload yang sama.
- Validasi reset frontend mengikuti aturan minimum 6 karakter backend existing; pesan en/id disesuaikan.
- Test setup menolak database selain nama berakhiran `_test` dan melarang DB_TEST_NAME sama dengan DB_NAME sebelum dropSchema berjalan.

Verifikasi terbaru: **143 test backend / 645 assertions**, **23 test frontend / 104 assertions**, typecheck/build kedua project dan lint frontend lulus. Awalnya suite backend gagal setup karena MySQL berhenti; OrbStack dan container mysql existing dinyalakan, lalu suite diulang pada database test terpisah. Tidak ada panggilan AI atau pengiriman pesan nyata.

**Browser belum diuji:** percobaan membuka tab Chrome localhost:3000 ditolak oleh saved origin permission. Tidak memakai browser lain, raw CDP, atau HTTP sebagai pengganti observasi halaman yang diblokir. Pengguna diberi panduan Settings → Computer use → Google Chrome → Manage. UAT desktop/mobile seluruh halaman dan layanan n8n live tetap pending; hasil test otomatis tidak disamakan dengan UAT browser.

## Route consolidation

Seluruh deklarasi endpoint sekarang berada di src/routes/api.ts, termasuk health dan dokumentasi OpenAPI. src/routes/social.ts dihapus. index.ts hanya memasang middleware global, memanggil registerRoutes(app), dan mengatur error/startup. Test memakai fungsi registrasi yang sama. URL /health, /api/docs, /api/swagger.yaml dan seluruh /api/* tetap sama. Body limit/auth/mutation limiter fitur dibatasi ke /social/*; signed-media dan callback service tetap didaftarkan sebelum auth pengguna.

## Follow-up: reporting validation and pagination

- Reporting query validation now runs through `zValidator('query', ..., validationHook)` in `routes/api.ts`, matching the route/controller boundary used by the original modules. The controller consumes validated input and only coordinates service/serialization/response.
- Shared `ApiResponse.paginate` returns `from: 0, to: 0` for empty and out-of-range pages. This fixes invalid UI ranges such as `1–0` or `981–1`; total/currentPage/lastPage semantics are preserved. Swagger documents the empty range.
- Added API regression tests for empty/out-of-range contact pagination and the standard 422 envelope for invalid reporting queries across overview/jobs/review/media/audit logs.
- Verification: full backend suite 146 passed, 670 assertions; typecheck and build passed. External SMTP/MinIO are mocked in the suite; no live publishing/AI dispatch was performed.
