# Audit dan refactor — 15 Oktober 2026

## Cakupan

Audit membaca perubahan lokal dan alur auth, reset password, user/contact, storage, logging, konfigurasi, migration, seeder, serta kontrak frontend. Perubahan manual (template email, logo, desain auth, alur resend) dipertahankan. Refactor ini bukan sertifikasi keamanan menyeluruh.

## Temuan dan tindakan

| Temuan | Perbaikan |
| --- | --- |
| Pola `database/` dan `seeders` di gitignore turut mengabaikan source migration/seeder | Pola diikat ke root; source di `src/database` dapat masuk Git |
| Access/refresh token masih menerima akun nonaktif; middleware mengakses ORM sendiri | AuthService memverifikasi JWT, subject, keberadaan dan status akun melalui UserService; kedua middleware memakai alur ini |
| Catch autentikasi terlalu luas mencakup lookup dan handler berikutnya | Hanya kegagalan verifikasi token diubah menjadi 401; error DB/domain mempertahankan maknanya |
| Request logger merekam reset token/OAuth code dari query | Nilai query dengan nama credential disamarkan sebagai `[REDACTED]` |
| Email `+` dirangkai langsung ke tautan reset | URLSearchParams mempertahankan alamat asli |
| API menyatakan email terkirim sebelum SMTP selesai | AuthService menerima IMailer dan menunggu hasil; kegagalan SMTP menghasilkan error generik 500 |
| `photo: null` diubah menjadi undefined, sehingga TypeORM melewati update | Null dipertahankan di entity dan service; input create/update tidak dimutasi |
| Daftar user memakai any dan serializer entity untuk hasil raw query | UserListRow bertipe dan serializer list khusus; createdAt tetap dikembalikan |
| Repository reset dipaksa memiliki CRUD generik yang tidak dipakai | Interface hanya memuat operasi use case penerbitan, validasi, dan konsumsi token |
| Route upload berisi logika bisnis dan proxy memakai bentuk error berbeda | StorageController → StorageService → adapter IStorage, wiring di storage.module.ts |
| Build bundler tidak mendeteksi error tipe | Command typecheck memakai TypeScript sebagai dev dependency dan tipe Bun eksplisit |

## Keputusan arsitektur

- Pertahankan arsitektur modular yang sudah ada; tidak menambah layer/domain framework tanpa kebutuhan konkret.
- Controller mengadaptasi HTTP, service mengoordinasikan use case, repository mengelola persistence dan transaksi. Adapter SMTP/storage dapat memakai interface kecil dan struktural.
- Service boleh memakai service modul lain. Wiring concrete dependencies berada di file module; middleware memakai service yang sudah diwiring, bukan ORM.
- `IBaseRepository` opsional: gunakan hanya jika seluruh operasi CRUD benar-benar diperlukan. Modul storage tidak memerlukan entity, migration, atau repository database.
- Helper murni tidak perlu interface tambahan. Kontrak I/O yang disuntikkan dibuat sesuai operasi yang dipakai.
- Null berarti hapus nilai nullable; undefined berarti field tidak diubah.
- Test transaksi dan API menggunakan MySQL nyata yang terisolasi. SMTP dan MinIO dimock pada batas adapter dalam suite standar; ini tidak membuktikan pengiriman email atau upload ke layanan nyata.

## Perilaku yang dipertahankan

MySQL saja, synchronize false, migration satu file pembuatan per tabel, migration/seeder melalui command di src/database. Request/resend menambah token, seluruh token user dihapus dalam transaksi saat satu token berhasil. Template HTML/plain text dan masa berlaku 10 jam tetap dipertahankan. Kegagalan SMTP tidak menghapus token terdahulu; pengguna dapat mencoba resend.

## Batas dan pekerjaan lanjutan

- JWT masih stateless: logout menghapus sesi client, tetapi belum mencabut JWT yang sudah diterbitkan. Reset password belum memiliki session-version/revocation untuk seluruh JWT. Ini memerlukan desain sesi dan migration tersendiri.
- Endpoint user/contact belum memiliki RBAC; jangan menganggap semua user sudah dibatasi berdasarkan role.
- `/proxy` tetap publik sesuai kontrak lama. Kebijakan akses object, pembatasan ukuran/MIME upload, dan rate limiting autentikasi perlu ditentukan sebelum deployment publik.
- Pencatatan file log masih sinkron; rotasi/retensi dan pengiriman ke log collector belum dirancang ulang.
- OAuth Google memerlukan client ID/secret yang benar; pengujian tidak menggunakan akun Google nyata. SMTP/MinIO produksi tetap perlu smoke test dengan konfigurasi layanan sendiri.

## Verifikasi

Jalankan `bun run typecheck`, `bun run build`, dan `bun test` pada database test terpisah. Regresi baru di `test/audit.test.ts` mencakup status akun, error domain, null foto, encoding email, kegagalan SMTP, redaksi credential, dan format error proxy. Suite reset tetap menguji transaksi bersamaan dan penghapusan semua token. CLI migration run/show/revert dan kedua command seed diuji pada database sementara, bukan data aplikasi.

Hasil verifikasi akhir: 122 test backend lolos (0 gagal), typecheck dan build lolos, serta seluruh command CLI yang diuji berhasil. SMTP/MinIO memakai mock adapter; pengiriman/upload nyata tidak diklaim lolos.
