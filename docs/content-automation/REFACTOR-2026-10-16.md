# Feature refactor — 2026-10-16

## Source of truth

Existing codebase conventions take priority over the PRD. Reuse MySQL, Hono, TypeORM, JWT, the existing MinIO helper, NuxtUI, API client and i18n. There is no `modules/social`, `pages/social`, `services/social`, `components/social`, or `composables/social` umbrella folder.

## Backend modules

| Module | Owned responsibilities and children |
| --- | --- |
| `src/modules/content/` | Batch metadata/consent; `media/` owns asset upload, original/preview access, signed access, MinIO and SVG safety adapters |
| `src/modules/ai-job/` | Job lifecycle, dispatch outbox, watchdog; `workflow/` owns n8n contracts, transport, claim and results |
| `src/modules/content-review/` | Draft, immutable revisions, optimistic concurrency and internal review |
| `src/modules/integration/` | Non-secret settings and dispatch configuration |
| `src/modules/reporting/` | Scoped lists, overview and audit entities |
| `src/modules/shared/` | Cross-feature transactional repository, entity registration, ownership context and HTTP helpers |

Every feature has its own `*.module.ts` composition root. `src/modules/shared/shared.module.ts` constructs only the shared transaction repository/context. Each feature module exports its own controllers and services, and routes import directly from the owner. The former root workflow.module.ts aggregator has been removed. The repository/unit-of-work remains shared because one AI-result transaction persists job, batch, result, render, draft and revision atomically. Ownership checks and batch-before-job locking stay centralized. No giant facade service/controller remains.

Table names, migrations, HTTP envelopes and `/api/*` wire contracts are preserved for existing n8n integrations. Folder organization is independent of the external API namespace. Migrations and seeders remain explicit commands, and `synchronize` remains false.

## Frontend features

- `app/services/{content,ai-job,content-review,integration,reporting}/`: API clients by feature; shared bearer/idempotency headers in `services/shared/`.
- `app/composables/content/useContentUpload.ts`: staging, progress and resume state.
- `app/composables/content-review/useContentStudio.ts`: editor/revision/review state.
- `app/composables/reporting/useContentRecords.ts`: filters, paging, download/archive and pending reloads.
- `app/components/content/`: private media; `content-review/`: rankings, preview, review history; `reporting/`: list view. Shared status badge is a top-level component.
- Types split into `content`, `ai-job`, `content-review`, `integration`, `reporting`, and `user-role`.
- Pages: `/overview`, `/content/upload`, `/content/media`, `/ai-jobs`, `/content-review`, `/content-review/studio`, `/activity-logs`, `/integration-settings`. Legacy `/social/*` page aliases were removed along with the old API prefix.
- Reusable formatting remains in `app/util/content.ts`; stateful behavior belongs in composables.

Fixed a filter race: a filter change while a request was active previously dropped the refresh. The list now schedules the latest reload, suppresses superseded results and avoids follow-up loads after unmount.

## MinIO reuse and legacy data

Storage now uses one private MINIO_BUCKET via the existing MinIO helper. Avatars use direct presigned URLs; originals/previews/renders retain authenticated or scoped signed access. The generic proxy and separate media bucket configuration have been removed.

`bun run media:import-local` copies old local objects referenced by database assets into MinIO, verifies SHA256, resumes existing matching originals, and never deletes local data. `LEGACY_MEDIA_ROOT` is only for this command; `SOCIAL_MEDIA_ROOT` is accepted as an old configuration alias. The local reader is read-only and is not used by runtime media routes.

Development verification copied and verified 28 objects to private MinIO. An unauthenticated original-object request returned HTTP 403. Local files remain as a backup. No AI calls or Telegram messages were triggered.
