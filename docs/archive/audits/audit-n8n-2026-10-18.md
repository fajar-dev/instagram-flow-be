# n8n integration verification — 2026-10-18

## Deployment

User chose to retain backend, worker and MySQL on the MacBook and use a tunnel for testing. Existing n8n Docker container on `festrack` is version 2.42.7. Three pre-existing workflows were inactive and preserved. Their backup and the nginx backup are restricted to root on the server.

New published workflow: `igFlowContentV3`, **IG Flow — AI Content and Review**, at https://n8n.fajarchan.my.id/workflow/igFlowContentV3.

Source and operating instructions: [integrations/n8n](../../operations/n8n.md). Secrets are stored in local ignored `.env` and n8n credentials, not the workflow artifact. No new application dependencies were needed.

The reverse SSH tunnel binds server loopback port 14000 to local backend port 4000. nginx exposes only service-authenticated job callback routes under `/ig-flow-api`. Existing n8n routes are preserved. The worker command and dashboard dispatcher control remain in use.

## Changes

- Modular workflow scripts validate intake, construct multimodal OpenAI requests, validate every asset ranking, generate Indonesian captions, and produce requested feed/story SVG layouts.
- Integration uses current camelCase `/api/jobs` contracts and direct MinIO presigned URLs. No legacy social route, local media storage, custom signing secret or media proxy was added.
- Backend reclaims a PROCESSING job only for its already assigned execution ID, after validating the dispatch event. This makes a lost claim response retryable; other executions remain excluded.
- Failures after a successful claim notify the backend with a safe fixed message and terminate the n8n execution as failed. HTTP retry and backend result hashing prevent duplicate draft creation.
- Initial live attempt reached the failure callback. Removing reliance on the sandbox's URL global allowed the next attempt to complete. Node programs now use sandbox-compatible primitives.

## Limits

This delivers AI preparation and internal review, not Instagram publication. The current application has no Meta account-linking/publish adapter. Telegram notifications were not connected or sent. No such external publishing action was performed.

The tunnel, backend, local MySQL and worker must remain online. MacBook sleep/offline breaks this testing setup. The n8n UI was accessible in Chrome and confirmed executions 3 and 6 as Succeeded, but the browser policy still denied `http://localhost:3000`; no frontend visual UAT is claimed. Backend integration checks are reported separately from browser checks.

Successful and failed execution data are retained by n8n's existing retention settings for troubleshooting; execution details are private operational data and may include presigned URLs and inbound headers. Do not share unredacted exports. Workflow/template exports in the repository contain credential references only.
